# v43 から Python TIR への段階的な移行候補

元 v43 の ZIP、step 15,000 の重み、既存の Kaggle job は変更しない。v43 の ALU・検索・日本語の経路を残し、別枝で Python の教材を少量追加するための隔離コードである。純 Python 化を達成したモデルではない。

## 固定した教材と分離

- 元 v43 教材は 268,032 行。評価問題の家族、Python 未見評価に対応する元行、誤ラベルを確認した GSM8K Japanese line 13 の **1 行だけ**を隔離した現候補は 258,463 行。回答に日本語文字を含むものは 235,598 行、形式論理命令を含むものは 16,675 行。元行を無条件に品質保証した数ではない。原票は `original_source_census_result_v2.json`。
- 元 CPU の全段実行と Python の実行結果が一致した変換候補は 24,836 行。代数 9,828、比較条件 15,000、SWE 8。既存変換の Python fence 74,532 個は純 v44 の行頭パーサに全件一致した。`check_python_fence_parser.py` が読取専用で確認する。
- SWE 由来 8 行は Python 実行観測の後が数字だけで、**日本語の根拠説明教材ではない**。多段 SWE と述語論理の十分な Python 橋はまだない。
- 現行の固定 seed・1% 枠で全1,000更新を予定した場合の Python 311枠は、代数110・比較201・SWE0。実行可能な先頭250更新では代数21・比較57・SWE0。したがって、この stage を SWE の Python 橋渡し学習と呼ばない。新しい SWE 全数候補を検証できた後、別版で層化選択を設計する。
- 元教材には品質上の懸念もある。たとえば JMultiWOZ 4,331 行には不自然な日本語の応答がある。上の行数を自然な会話能力の保証として扱わない。GSM の誤ラベルは元原物を変更せず、該当 SHA の行だけ除外する。
- 評価・未見問題の家族は学習から隔離する。Python 行には明示 cue を付け、同じ質問に異なる旧 ALU と Python の回答を書き出させる直接競合を避ける。cue なしで自律的に Python を選ぶ能力は別に測る。

## 実行と保存の条件

`replay_python_full.py` は変換全 24,836 行を Linux の隔離 Python 実行器で再実行し、元 ZIP 行・実行観測・回答を照合する。Windows では元実行器が資源制限のため動かない。現時点でこの**独立した全数再実行は未完了**であり、`train_hybrid_stage.py` は COMPLETE 原票なしでは学習を拒否する。WSL Ubuntu に必要な torch も現環境にはない。Kaggle の使い捨て CPU/Linux で実行可能な設計で、既存 GPU job は再起動しない。

学習には、元 v43 の SWE200 全文と元採点器の固定ベースライン、および同じ親の固定 44 問の学習前原回答が要る。固定 44 問は SWE20、検索8、論理8、日本語説明8。SWE20 は旧 CPU 経路、明示 cue 付き Python、cue なし Python の 3 条件で生成する。他24問は旧形式。親・0%・1% の全条件では **84 × 3 = 252 本**を、各最大 2,048 位置、強制 EOS なしで測る。44 問は途中停止の診断で、元の Tier 1〜8 全評価や旧 SWE200 の保持証明には使わない。

`train_hybrid_stage.py` は元 v43 重みを strict 読込する。親には optimizer/RNG/cursor が保存されていないため、初回だけ新しい Adam と固定 seed を使う。最初の保存後は Adam・CPU/CUDA/Python/NumPy RNG・教材予定・更新 cursor を一体で継承する。0% 対照と 1% 介入は同じ元教材スロットを消費し、共通の最大行長でマイクロバッチ境界を揃える。Python 比率は行数ではなく、真の次文字と EOS に損失を掛けた位置数で上限を課す。ツール観測位置は損失から除く。CE は全 active 位置で正規化し、圧縮損失 0.2 は各行の二乗誤差の和を64で割る。**この正規化は元 v43 のマイクロバッチ等重み式から変更した**。両 arm 共通だが、1% 比較が示せるのは「Python 変換教材を導入した処置全体」の効果で、Python 教師信号だけの因果効果ではない。

今ある実行入口は **stage 1 の 250 更新で必ず停止**する。そこで親・0%・1% の同一問題原回答を保存し、旧 SWE・検索・論理・日本語の崩れと、実 Python 呼出し・最終回答を分けて調べる。次の 250 更新や stage 2〜4 への昇格 gate は未実装であり、現コードは拒否する。たとえ途中44問が良くても、本採用には元 Tier 1〜8、SWE200 の全問、自然 EOS、原回答、Python 実行ログの別の閉包が要る。

学習・評価とも、Root が公式の fresh 無料 quota、未使用 hold、既存 job 状態を確認した**別の one-use claim**を必要とする。保守予約は `(実行 hard stop + 保存余裕) × GPU 台数` の device 秒以上。評価は `launch_fixed_diagnostic_bounded.py` の子プロセス watchdog からのみ起動し、時間超過時は終了済み子が flush した完全な行だけを SHA とケース順で検査して PARTIAL を確定する。途中行や不明な結果を自動再送しない。

現在、別の Kaggle job が 2 件稼働し、公式 quota の取得は HTTP 500 で fresh 無料残を確認できない。**この枝の GPU 更新・回答生成は 0 件**。ソース整合と CPU 小型試験の通過をモデル性能の改善と呼ばない。
