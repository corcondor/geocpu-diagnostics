# GeoCPU 純 v44 の反復方向介入候補

これは**未実行の調査用コード**です。純 v44 Hotfix の保存重み、語彙、生成器、学習データを変更しません。実モデルの読み込み、Kaggle 起動、学習、チェックポイント保存も行いません。ここで通した試験は小型の合成行列だけです。

## 原典と GeoCPU への対応

Takehi らの[原報告](https://rikiyat.github.io/blog/weight-space-programming/)と[実験記録](https://github.com/RikiyaT/lm_understand-logs/tree/main/exp8_math)では、Qwen3.5-0.8B の正常な思考継続と反復する思考継続の活性差から方向を得ました。MLP 出力行列の選んだ列について、`W' = W - α·u·(mask ⊙ (uᵀW))` を適用しました。この候補は**数式だけ**を参照します。Qwen の層番号、64 列という列数、列 ID、1024 次元方向、介入強度 6 は GeoCPU に移していません。

純 v44 の `GeoCPU_CED_v1.py` にある各 FFN は `Linear(768,3072) → GELU → Linear(3072,768)` です。実モデルで使う際は出力行列が **768 行 × 3,072 列**であることを再検査します。対象候補は `base.encoder.N`（10 層）、`base.decoder.N`（14 層）、`fine_decoder.N`（10 層）の FFN 出力です。どの層が反復に寄与するかは未特定です。

## 手順と境界

1. 先に、未改変の v43 親と純 v44 子を同じ純 v44 生成器・同じプロンプト・同じ設定で読み取り専用比較します。保存済み回答だけから、重みの単一方向が反復の原因だと決めません。
2. **発見用**の train/practice 問題で、同一プロンプトと同一接頭文から正常な継続と反復する継続を対にします。元の純 v44 重みを教師強制で走らせ、各層の残差出力と `ffn[2]` 入力の末尾区間平均を取得します。ここで使う対は評価用の問題と分離します。この採取器はまだありません。
3. 各対について「反復 − 正常」の残差活性差を平均し、単位方向 `u` を作ります。各 FFN 列の点数は「同じ対での FFN 入力活性差 × その列が `u` へ書く量」の平均です。正の点数を持つ列から `top_k` 本を選びます。`top_k` と強度 `α` は発見用問題だけで決めます。最低 4 対を要求します。
4. `temporary_output_hook` は推論時に `ffn[2]` の出力へ `(W'−W)a` だけを加えます。元の重みは変更しません。`finally` でフックを解除します。`edited_weight` は比較用の**新しい**テンソルを返します。いずれもチェックポイントへ書き込みません。
5. 評価時は元の純 v44 生成処理に、同一の語彙、プロンプト、`arm=learned`、反復ペナルティ 1.0、2,048 生成トークン上限を渡します。評価入口 `evaluate_heldout` は生成関数と正誤判定関数を外部から受け取ります。元の回答全文、モデル生成部分、終了理由、反復指標、正誤を基準・強度 0・直交方向・候補の 4 条件で返します。未見の評価問題を方向・列・強度の選択に使いません。

原典の「直交方向」は、方向だけ変えて変更量が小さくならないよう、編集差分のフロベニウスノルムを候補と合わせます。強度 0 の条件は、フックの存在だけで出力が変わらないことを確認する条件です。評価入口は強度 0 と無介入の原回答、生成文字、終了理由、正誤が一致しなければ停止します。反復は**モデル自身が生成した文字列**の末尾の完全一致句を1文字周期から測り、道具が注入した文字列を混ぜません。正誤はタスク固有の判定関数が与える必要があります。

## 未検証の点

- 実チェックポイントで、正常な回答と反復回答の十分な対はまだ確定していません。活性方向も列候補も、実データからは推定していません。
- 全文教師強制と逐次生成が実 247,568,664 パラメータの重みで一致するかは未測定です。特に `base.decoder` は圧縮後の位置で動くため、末尾区間の対応を別途点検する必要があります。
- 評価入口は生成関数を自動設定しません。純 v44 の Python 実行器は対抗的な隔離環境ではないため、実生成には既存の隔離済み評価環境と元の設定が必要です。
- 反復が減っても、自然終了と回答の正しさが改善しなければ修復とは判定できません。旧能力と道具利用の保持評価も必要です。
