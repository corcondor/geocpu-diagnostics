# v43 の CPU 教材を純 Python v44 へ移す有界試作

**結果：元の v43 教材の先頭 128 行から 12 行だけを候補化し、各行の全命令を元の CPU 回路と純 v44 の Python 実行器で照合しました。学習・モデル評価・重み変更は行っていません。**

対象は `G:/マイドライブ/GeoCPU_Frontier_CoTraining_v43/Grand_cotraining_v43.zip` 内の `data/train_v43_knowledge_unified.jsonl` です。ZIP の SHA256 は `0102dc9b01b4b795c3123b18cefc7a8734e47a06dd85292af464d3232704d198` です。旧教材の全数と検索教材の限界は[先行調査](../../../reports/v44fix/2026-11-03-v43-train-to-python-feasibility.md)を参照してください。

## 受理条件

1. 元の `prompt` と `full_text` の境界を保持します。例えば元の代数行は `full_text = prompt + " " + target` なので、候補の `target` も先頭空白を持ちます。`問題: …\n思考:` を会話形式へ変えません。
2. 元の `<命令> => [レジスタ=値]` を全て解析します。対応命令は `SET/MOV/ADD/SUB/MUL/DIV/MOD/INC/DEC` に限定します。対応しない命令、対にならない観測、9 回以上の呼び出しは拒否します。
3. 元 v43 の `qwenputer_controller_v30.py` と `cpu_circuit_v30.py` を使い、各命令のレジスタ値を再計算します。元の観測と全段一致する場合だけ進めます。さらに元の問題文から最終値を独立に計算できる代数・個数比較・制限した SWE ループだけ受理します。
   実行時にこの 2 ファイルと対象 ZIP 内の元ファイルを全バイト比較します。今回の SHA256 は順に `e452bd0c5cf4c745b3de2276acbdcc67a4022f5329e4d8513a87587a8cb36e8e` と `fe3a5692136c9c055bae17eeeed395bea0516bdac3b51124c0c5b0cb768437d2` で一致しました。
4. 旧教材の文字列を Python として実行しません。厳密に解析した許可命令からコードを組み立て、純 v44 の `PythonExecutor` に渡します。Python の実出力が各段の元 CPU 観測と一致した場合だけ、コードと実観測を候補に入れます。
5. 実観測の文字位置を `target_segments` の `role=tool, train=false` として損失対象外にします。モデル自身が書く説明とコードは学習対象です。真の EOS は学習対象です。純 v44 の `encode_supervision` で語彙と 8192 位置上限も確認します。
6. 元 ZIP の同梱評価・保持用 8 ファイル、計 11,388 個の固有の正確な問題文と比較します。完全一致および Unicode 正規化後の一致は候補から除外します。全数調査で旧学習行 7,000 行が同梱の aligned 評価 200 問と完全一致することが判明しており、この試作でも同じ除外を実行します。

32 ビット値は元 CPU に合わせて符号なしの `0` から `2^32-1` で扱います。負の定数も 32 ビットへ丸めます。割り算・剰余の除数が `0` の場合、元 CPU と同じく `1` に置き換えます。レジスタ名 `R10` は `R2` へ丸めます。これらは実回路と Python 実行器の両方で確認しました。
