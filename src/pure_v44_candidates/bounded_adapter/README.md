# v43親重みを保つ小さな追加学習部分

このフォルダーは、純Pythonのコード実行を学ぶ**隔離した候補枝**です。実モデルの学習・生成・性能改善はまだ実施していません。v43の保存重みも変更していません。現在の公開教材と旧CPU変換は全件検証が未完了であり、GPU起動条件を満たしていません。

## 変更する計算

v43の神経重みを厳格に読み込んだ後、親の全パラメータを凍結します。出力ヘッド `base.head` と、詳細復号器の各 `fine_decoder.*.ffn.2` の線形変換に、低ランクの残差 `B(Ax) × alpha/rank` だけを加えます。`B` をゼロで初期化するため、追加直後の出力は元の親と同じです。元の行列はモジュール内に保持し、その値を学習しません。

この対象を選んだ理由は、純v44の教師条件付き学習と生成の両方が `base.head` を通ること、詳細復号器が同じ生成経路に入ることです。出力ヘッドだけでPythonの指示選択と長い説明を学べるかは未測定です。モデル全体247,568,664個の値を再び同時更新する案は採用していません。

## 導入順序

1. v43 step15,000のチェックポイントをファイルSHAで確認し、既存の `load_v43_neural_weights` で純Pythonモデルへ厳格に読み込みます。
2. **その後** `install_adapters(model, AdapterSpec(rank=8, alpha=8))` を呼びます。元の `model.state_dict()` 形式は変わるため、取り付け前に親を読み込む順番が必要です。
3. `adapter_parameters(model, names)` だけを最適化器へ渡します。元モデルのパラメータに勾配があれば実行を拒否します。
4. 元の問い・新しい公開Python実行例を学習に使う前に、評価問題の完全一致・派生形・同一系列を除外します。旧CPU教材を移す場合は元CPUとPythonの実行結果を行ごとに照合します。変換試作は隣の `v43_alu_to_python/` にあります。
5. 差分だけを専用ファイルへ保存します。親チェックポイントのSHA、教材マニフェストのSHA、対象モジュール名、最適化器、更新数を保存し、再開時に照合します。乱数状態の復元は呼出側の責任であり、保存しただけで完全再現とは称しません。

## 実学習の入口と停止条件

- `build_curriculum.py` は、元Numina parquet、Dolly JSON、Magicoder JSONL、v43 ZIPから改めて選別し、旧CPU変換結果と結びます。旧v44のtrain/未実行観測は入力として使いません。NuminaのPython観測は選別時にも実行します。旧v43の実回答・旧技能評価・未見評価の3ファイルも入力必須です。元公開データが見つからなければ拒否します。反復露出は重複した新問題に数えません。
- 元v43の語彙と設定ファイルを固定SHAで照合し、学習系列をその`max_positions=2048`以内に収めます。元v43 ZIPに含まれる8件の評価manifestをすべて同SHAで渡さなければ教材作成を止めます。未見評価行の系列IDは問いの正規化形から再計算し、入力枠だけを変えた重複を拒否します。
- `independent_verify.py` は、各公開Numina行のPython実行・観測を元の `problem/solution/messages` から再構築し、旧CPU変換行は元回路とPython実行器で全段照合します。Dolly・Magicoder・v43言語保持行は元フィールドから再構築します。全行の原物SHAと実行票を別保存します。公開コードを実行するので、秘密情報のない隔離した使い捨て環境でのみ実行します。
- `admission.py` はその別実行票の原物SHA・全行SHA・verifierソースSHAを照合します。教材の自己申告フラグ、64桁の文字列だけでは通りません。学習候補は最低5万の異なるprompt、Python実行候補1万（元Numina 5千以上・旧CPU変換1万以上）、Dolly日本語1万、Magicoder非Pythonコード1万、旧v43の**CPU命令や検索の無い**言語・知識保持行1万を要求します。評価問題との一致と同系列も拒否します。閾値は事前固定し、選別後に足りなければGPU学習を拒否します。意味的な言い換え全件の非重複は証明していません。
- `train_stage.py` は元v43の神経重みをstrict loadし、追加部分だけを1～250更新します。学習式と生成の両方で追加部分が効くか、実モデルで先頭logitのsmokeを通してから更新します。UTC期限の3分前までに停止し、最大25更新ごとに差分・Adam・CPU/CUDA/Python乱数状態を保存します。実効差分 `ΔW=(alpha/r)BA` のFrobenius normが各元行列の1%を超える更新は、差分・Adam・乱数・cursorを戻して停止します。この1%は事前固定値です。ノルム制約と保持評価は別です。
- `paired_eval.py` は親と追加差分を同じ純Python生成経路・同じ未学習問題・最大2,048生成tokenで比較し、無加工の原回答と実Python呼出しを保存します。旧v43元CPU経路の正答は、別にpinした `v43_original_answers.jsonl` からのみ読みます。
- `blind_packet.py` はarm名を隠した採点packetと別のrolemapを作り、採点後にpacketだけを読んでgrade SHAをpinします。`retention_gate.py` はそのpinを先に検査し、rolemapを開いて原回答と採点を照合します。rolemapを採点者に渡さない運用は必要です。
- 次の学習段階へ進む際は、前段の保持判定JSONだけでは受理しません。採点packet、rolemap、採点票、全原回答、教材、独立再実行票、元v43全文原回答を読み直し、前段判定を再計算します。別Kaggle環境へ移す場合は、7種類の証拠パスを列挙したJSONとそのSHAを指定します。旧技能で元v43が自然終了した問は、追加部分でも全問自然終了を要求します。

この保持gateの `PASS` は**次の最大250更新ステージへの継続判定だけ**です。旧v43のCPU課題には、純Python経路で意味正答し、かつ各問で実Python実行が成功したかを別軸で要求します。公開採用には従来のTier1～8を全て同じ条件で再評価し、原回答と実Python呼出しの原票を別に封印する必要があります。このコードはTier1～8を置換しません。

現時点で公開原物4ファイルは取得・SHA確認済みです。旧v43の同一問CPU-native全文回答と外部採点、旧技能/未見評価の固定票、全行再実行票、実統合モデルのGPU smoke、学習後の原回答は揃っていません。したがって**コードの準備と新GPUの起動可能状態は別**です。従来の旧CPU命令logitをKLで保持しません。その損失はPython移行を妨げます。旧SWEの保持は、実行結果が一致したPython変換行と旧正答問題の意味採点で確認します。

## 合格条件

同じ純Python生成経路、同じ問い、最大2,048生成トークンで、親と追加部分ありの原回答を保存します。旧技能に属する既習問題と、学習へ混ぜていない新しい数値・言い回し・日本語説明を別々に採点します。旧正答問題の劣化や自然な終了の低下があれば、候補を継続モデルへ昇格しません。Python実行の成功は、実行器がコードを処理して返した記録で判定します。文字としてコードや実行結果を表示しただけでは成功と数えません。
