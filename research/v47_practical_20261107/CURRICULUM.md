## 教える内容

学習用16familyは、出荷済みの請求集計、個数で重みを付ける平均価格、在庫と発注数、混在単位の換算、日付をまたぐ時間、重複ログの更新、返品を含む地域集計、指定定義でのパーセンタイル、欠測を除く中央値、商品の箱詰め、境界条件の修正、集計コードの修正、数値ソートの修正、予約の重なり、優先順位による作業選択、否定条件での行選択です。

追加評価だけに入れた4familyは、稼働区間の和集合、連続する期間の最大合計、依存関係のある作業の終了時刻、文字列の編集距離です。「新しいfamily」とは**この追加教材のtrain/devには存在しない**という意味です。過去の学習全体に同じ概念がなかったことは確認していません。

この教材は新規に作った業務表・プログラムの課題であり、外部の実業務ログではありません。各familyの入力表やテストケースを変えて展開しています。512行を512種類の独立したアルゴリズムや知識の獲得と数えません。既知familyのdev/evalは別の入力群ですが、アルゴリズムのテンプレートを共有します。集計時には「既知family192」と「この追加教材で未使用のfamily48」を分けてください。

## 学習形式と境界

各行には`prompt`、`target`、`full_text`、`loss_mask_spans`があり、`full_text == prompt + target`です。`_v46_group`は`practical_python_multistep_v1`です。既存データを変更せずに追加できる形式です。

Pythonは現行と同じ` ```python `のコードフェンスを使います。観測は元の`tir_engine_v44r1.observation_text`から生成し、先頭の改行から` ```output `の閉じフェンス後の改行までをマスクします。修正したコード、結果の読み取り、日本語の最終回答、真のEOSは学習対象です。EOSはデータ本文へ擬似文字として付けず、既存ローダーのEOS付加を使います。

コード修正3familyでは、壊れたコードと実際の`AssertionError`を**入力側**に置きます。正解側には修正コード・3個のテスト・新しい入力への適用・最終回答だけがあります。既知の誤コードをモデル自身が書き始めることを正解にしていません。入力内のコードを実行した状態が漏れないよう、教師回答の実行前にワーカーをリセットしています。

教師回答は2回のPython実行を含み、後半は前半が作った表・変数・修正済み関数を利用します。ただし、この全課題が必ず2回に分けて実行しなければ解けない、という意味ではありません。評価では**正しい最終結果と実行の整合**を主に測り、2回呼び出しただけで正解扱いしません。追加データだけで学習すると道具の過剰使用を教えるおそれがあるため、既存の会話・論理・ALU・道具不要のデータを混ぜて維持する前提です。

`final_answer_line`には日本語の最終回答1行を別保存しています。例えば`答え: 12976 円。出荷済みの行だけを合計した請求額です。`の形式です。答えだけを教える対照実験では、同じ`prompt`とこの行を使えます。`reference`には数値文字列と単位、`reference_final_answer`には値と単位を保存しています。

## 再生成とチェック

既に検算したJSONLを同梱してあります。再生成は新しい出力先を指定してください。元のチェックポイント、教材、評価には書き込みません。既存の出力ファイルがあれば上書きせず停止します。

```bash
python build_curriculum.py \
  --r6-bundle /path/to/GeoCPU_v47_fullmodel_bundle_v1_READY.zip \
  --frozen-root ./frozen \
  --output ./new_practical_data

python -m unittest discover -s tests -p test_curriculum.py -v
```

`--r6-bundle`には外側のv47 bundleまたはその`assets/r6_bundle.zip`を指定できます。元のR6 SHA-256を照合してから、その中の語彙・正規化表・ワーカーを読み込みます。原本が変わっていれば黙って別の実装で検算しません。外部の問題文を追加で照合する場合は`--heldout <JSON/JSONL>`を繰り返して指定できます。

9件のCPUテストは、データ件数とハッシュ、出力観測だけがマスクされていること、誤ったマスクの拒否、分割間の問題・入力群の重複、未使用familyの分離、参照値と記録済み実行結果の一致、誤コードが教師targetに入らないこと、正規化重複検出、原ランタイムのハッシュ不一致の拒否を確認します。
