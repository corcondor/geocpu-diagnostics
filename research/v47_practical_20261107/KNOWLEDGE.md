# 知識・検索教材の追加分

## 目的と確定した内容

既存の公開教材スナップショットを使い、「前の検索結果から次の検索対象を選ぶ」「根拠がそろったら止める」「指定された答え方で結論を出す」を追加で教えます。元のJMMLU、JamC-QA、T1〜T8の問題・採点は変更していません。

| ファイル | 行数 | 元の検索連鎖数 | 用途 |
| --- | ---: | ---: | --- |
| `data/knowledge_train.jsonl` | **336** | **168** | 追加学習。記号回答と選択肢本文回答の2形式 |
| `data/knowledge_dev.jsonl` | **4** | **2** | 同条件の4択形式チェック |
| `data/knowledge_free_dev.jsonl` | **64** | **64** | 選択肢を見せない追加の検索・自由回答診断 |

学習の168連鎖はJEMHopQA由来40、Wikidata由来128です。自由回答診断はJEMHopQA由来32、Wikidata由来32です。trainは2段82連鎖と3段86連鎖、自由回答devは2段47連鎖と3段17連鎖です。336行を336個の新しい独立した知識と数えません。168連鎖の知識自体は既存のtrain側教材に入っており、今回増やしたのは行動・回答形式の教師例です。

## 4択の作り方を修正した理由

初期案は正解候補を全分野の値から選んでいたため、例えば国が1つ、都市が3つの選択肢だけで答えを推測しやすい組がありました。今回の正本では、**同じ元split、同じ最後の関係から得られる値だけ**を選択肢にしています。「所在国」の問題なら「所在国」として登録された値を使います。現在の検索器でその候補を実際に取得できることも確認しています。

異なる誤答候補が3個そろわなければ、その4択例を除外します。異なる関係の値で埋め合わせません。この条件により、train候補328連鎖のうち158連鎖を候補不足、2連鎖を検索結果または連鎖の不整合で除外しました。採用したtrainでは、正解位置A〜Dがそれぞれ84行です。

devのWikidataには所在国・首都がそれぞれ3種類しかなく、同型の4択を作れません。dev候補64連鎖のうち62連鎖を4択から除外した結果、4択devは4行になりました。**この4行から一般教養の汎化を判断しません。** 代わりに同じ元dev64連鎖から選択肢なしの自由回答診断を作っています。これは既存devの別形式です。新たに64個の独立した連鎖を集めたわけではありません。

同じ関係の候補を使うことで明らかな型の手掛かりは減りますが、別名・同義語・文脈上の曖昧さを人が全件検証したわけではありません。元のJMMLU/JamC-QA全件の評価と、この追加診断は別々に報告してください。

## 実際に確認したこと

生成とは別の検索器インスタンスで**571回の検索**を再実行し、保存された観測と一致することを確認しました。train168連鎖で254箇所、4択dev2連鎖で2箇所、自由回答dev64連鎖で81箇所について、次の検索対象が直前の結果本文の値と完全一致しています。最終結果の値も参照回答と完全一致しています。4択devの2連鎖は自由回答devにも含まれるため、これらを足して独立した234連鎖と数えません。

`<SEARCH ...>`の後のマスクは、現行`integrated_model_v44fix.py`の挿入規則` => {検索結果} `と文字単位で一致します。検索指示・観測後の文章・最終回答はマスクに含めません。原コードの該当ASTも照合しました。語彙欠落・正規化による変化は0で、最長の教材はEOS込み559文字です。

元のtrain/devは連鎖IDと元の問題の系譜で分離しています。Wikidataは同じ元問題の検索深さ違いも同じ系譜として照合しました。追加trainの問題と誤答候補の両方に対し、元devの系譜との交差は0です。

元評価の33,822プロンプトビューとの正規化完全一致は、新しい入力形式についてtrain/dev/free_devすべて0でした。さらに元の質問文を照合するとtrainは0、4択devは4行、自由回答devは64行が一致します。devは意図して元devから作った別形式なので、この一致を隠して「完全に新しい評価」とは扱いません。完全一致検査は、意味的な類似や別データから同じ事実が学習された可能性まで否定するものではありません。

11件のCPUテストで、参照値、実検索結果、マスク境界、選択肢と記号の対応、同じ関係・splitからの候補選択、系譜と元行のハッシュ、語彙、元評価との重複の報告、選択肢なし診断の分離を確認しました。これらはデータ検証です。モデルの生成を評価したものではなく、GPU学習・GPU評価は0です。

## 出典とライセンスの扱い

原スナップショットは`GeoCPU_public_search_science_20261105_v4`です。根拠文は注釈付きの関係を短い文へ変換したものです。**原典の各事実を改めて調べた検証ではなく、固定スナップショット内の整合性確認**です。Wikipediaの原文を新たに収集したものでもありません。時期によって変わる事実が現在も正しいことは保証していません。

JEMHopQAの原manifestには出典`https://github.com/aiishii/JEMHopQA`、版`corpus_ver1.2`、ライセンス`CC BY-SA 4.0`が記録されています。Wikidata由来の元教材は`CC0`と表示されています。各問題と各選択肢には、それぞれの元行ID、元split、元行ハッシュ、関係、出典系列、ライセンス表示を保存しました。`data/knowledge_support/`に原manifestと使用した元行の写しを含めています。今回の変更を含むJEMHopQA由来部分にも元の表示を残しています。

現在の学習素材は地理的な関係、人物・団体などの限定された関係が中心です。これだけでJMMLUの学術分野やJamC-QAの文化的知識を広く補ったとは言えません。**今回確認できた改善案は、既存の根拠を実際の検索行動と正しい答え方につなぐ教材の追加**です。新しい事実の大幅拡充は、別途、出典・評価との分離・検索コーパスの収録範囲を確認して進める作業です。

## 計算量と最小実行

追加train336行は、現行の文字単位語彙でEOS込み142,045トークン、損失対象39,285トークンです。検索結果を読む計算は必要ですが、その文字列をモデルに生成させる損失は掛けません。モデルのパラメータ数は変わりません。GPU時間・性能改善量は未測定です。

```bash
python build_knowledge.py \
  --r6-bundle /path/to/GeoCPU_v47_fullmodel_bundle_v1_READY.zip \
  --frozen-root ./frozen \
  --output ./new_knowledge_data

python -m unittest discover -s tests -p test_knowledge.py -v
```

学習側の再現には`knowledge_support/corpus_train.jsonl`、今回のdev診断には`knowledge_support/corpus_dev.jsonl`を使います。比較するチェックポイント間で、同じコーパス・生成上限・採点条件を共有してください。元T1〜T8の検索コーパスは原条件のままです。

同梱データの`final_answer_line`は、答えだけを教える対照条件に使える最終回答行です。`reference_final_answer`は記号または値、`reference_answer_text`は根拠から得る値です。`knowledge_free_dev.jsonl`は`answer_format="free_text"`、`options=[]`、`split="dev"`で、学習へ追加しません。

採用判断では、基礎能力を維持したうえで、元の知識試験、元の検索評価、選択肢なし診断での最終正答が改善するかを確認します。4択形式だけの改善や、検索回数が増えただけの変化は、一般教養全体の改善とは区別して報告してください。
