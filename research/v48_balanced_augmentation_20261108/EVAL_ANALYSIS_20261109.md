# GeoCPU v48（40,500→61,500）評価の解析（第 2 版：独立レビューと Kaggle 結果を反映）

**English TL;DR (v2).** v48 (21,000 A100 updates, LR 3e-6) taught the *output format* of four new task families but not the skills
(held-out 8–11 %; the 4-option Japanese family is at its 25 % chance level), while program/symbolic tasks stayed high
(T1 99.5 %, T2 88 %, T4-SWE 97.6 %). The legacy **T5 fell from 54.5 % (step 30,500) to 39.5 % (step 61,500)**, but T5 is *not* a reading test:
every option cites a premise number and (1)=entailed, (2)=contradicted, (3)=undetermined holds for 400/400 test items and 5,552/5,552 training rows,
so a number rule scores 100 %. The step-40,500 T5 was never measured. Our first Kaggle T5 re-measurement is **invalid** (generation cap 192 cut every output
before the decisive tokens; both checkpoints produced byte-identical text for all 400 prompts). Valid Kaggle results: JMMLU with rotated options is at chance for both
checkpoints (24.6 % vs 24.9 %, "A" chosen 77–81 %), T6 search is ~0 for both. The first version of this document argued from a small KL to the parent that v48 barely changed
legacy behaviour; independent review showed that argument cannot see T5 and it is **withdrawn**. Next: teacher-forced measurement of the decisive tokens on every checkpoint.

T5 の操作子別（30,500 → 61,500）：含意 71 → 38、矛盾 63 → 46、導けない 42 → 39、必ずしも正しいとはいえない 42 → 35。低下は含意と矛盾に集中し、不明系はほぼ不変（84 → 74 /200）。

- 40,500 の T5 は、評価ステージが T4 で GPU メモリ不足（T4 15 GB）になり、**一度も走っていない**。
- T3 の選択式と JMMLU は偶然水準に張り付いているため、動かなくても「保持された」証拠にならない。T2 は天井近く。
- プログラム・記号系（T1、T2、T4-SWE）は高いまま。T1 は 86.0 → 96.0 → 99.5 と動いている（同じ学習設定でも 10 点動く＝T5 の 15 点も動き得る大きさ）。

## 3. 解析

### 3.1 学習の実態（訂正）
- 「バッチ 64・36,864 token」は上限。実測の 1 更新は平均 55.0 行、入力約 18,194 token、教師約 8,322 token（21,000 更新の合計：提示 1,155,008 行、教師 174,759,265 token）。LR 3e-6 固定、親 40,500 への KL（重み 1.0）。
- 新教材（v48_additive_only）は教師 token の 1.1897 %（2,079,114 / 174,759,265）。親の行 423,348 は保存、親の practical 848 行を 8 倍重みにする複製 5,936 行を追加。KL は新教材以外のすべての行に掛かる。
- **T5 型の教材は親に含まれる（確認済み）**：JNLI 型 5,552 行（original_parent の 1.92 %、教師文字数の 4.47 %）。テストとのプロンプト一致 0、文脈一致 0（漏えいなし）。応答は平均 421 字。

### 3.2 「KL が小さいから v48 は動かしていない」は取り下げ
初版は「親への KL≈0.004 → 旧来の挙動は不変 → T5 の低下は 30,500→40,500 の段で起きた可能性が高い」と推論した。独立レビュー（再計算で全員が確認）：
1. KL は学習バッチ上の**教師強制**・**1 トークン平均**。T5 の成否は応答 421 字のうち**答えを決める約 2 トークン**で決まるので、T5 が完全に壊れても KL は約 0.00004 しか動かず、ログの揺れ（標準偏差 0.0004〜0.0005）の約 1/10。KL は T5 を見ていない。
2. 30,500→40,500 の段も同水準（0.0020 → 0.0038）で同じ設定。同じ指標が両段に当てはまるので、どちらが原因かを区別できない。
3. 同じ設定で T1 は +10 点（86.0 → 96.0）、+3.5 点（96.0 → 99.5）動いている。
4. 30,500→40,500 の段は新規 848 行を 1 行あたり約 20 回（計 17,046 回）提示し、教師 token の 6.03 %（v48 の約 5 倍）を占めた。v48 より「小さい摂動」ではない。
5. KL の錨は段ごとに直前の親へ付け替えられるので、段をまたぐ累積のずれは測っていない。

**結論：T5 の低下が 30,500→40,500 にあるか v48 にあるかは、現時点で分からない。**

### 3.3 T5 は読解を測っていない（訂正）
- 初版の「読解（前提と選択肢の突き合わせ）が要る」は誤り。各選択肢は「（k）に関して、…」と前提番号を引用し、**（1）＝含意、（2）＝矛盾、（3）＝不明**が 100 文脈すべてで成り立つ（テスト 400/400、学習 5,552/5,552、例外 0）。指示 4 種を真・偽・不明に直して該当番号を選ぶだけで 400/400 = 100 %。
- 参考：文字の重なりだけの規則は 49〜67 %（向きは結果を見て選んだ後付け）、指示を無視して常に「不明」の選択肢を選ぶ方策は 50 %。
- 正しい偶然水準は 33.3 ± 2.4 %（1 標準偏差）。61,500 の 39.5 %（158/400）は偶然より有意に高い（片側 p=0.006）が、「常に不明」50 % より有意に低い（p=1.6e-5）。30,500 の 54.5 % は 50 % をわずかに上回る程度（p=0.040）。**初版の「39.75 %（指示ごとの最頻の文字）と区別できない」は、正解を見て選んだ後付けの基準なので根拠にならない。**
- したがって T5 の点数は「（k）番号の索引」という壊れやすい近道を使えているかの目安であって、読解力の証拠ではない。含意・矛盾（番号 (1)(2) を使う操作）が最も落ちた形は、近道の喪失と整合的だが、出力形式の変化とも区別できていない。

### 3.4 統計
- 30,500→61,500 の 15 点低下は標本のゆらぎでは説明できない（対応なし z=4.25、p=2.1e-5。1 文脈 4 問を 1 個とみなす最悪ケースでも差の 95 % 区間 [1.3, 28.7] 点）。→「ゆらぎではない。原因は測定条件・近道・形式のどれか」。
- 400 問は独立ではない（100 文脈 × 4 指示）。以後の分析単位は文脈（100）。
- 3 つの重みの 3 対比較は多重比較になる（全て同一でも、いずれかが p<0.05 になる確率 19〜28 %）。

### 3.5 Kaggle T4×2 の測定結果（2026-11-09、30,500 と 61,500、同条件）
| | 30,500 | 61,500 |
|---|---:|---:|
| JMMLU 回転 0〜3 の正解率 | 23.35 / 24.69 / 25.40 / 26.19 % | 23.16 / 24.63 / 25.19 / 26.81 % |
| **偏りを除いた正解率（7,534 問）** | **24.6 %**（23.6–25.6） | **24.9 %**（23.9–25.9） |
| 「A」を選んだ割合 | 77.1 % | 80.9 % |
| 対応のある差 | +0.31 点、McNemar p=0.41（有意差なし） | |
| T6（21 種の問い） | 答えが出た 1/21、使った 1/21 | 0/21 |

- JMMLU：回転 0 は A100 の元の値（23.41 % / 23.14 %）とほぼ一致（T4 と A100 で読み出しは同じ）。偏りを除いても偶然水準で、2 つの重みに差はない。
- **T5 は無効**：生成上限 192 は答えを決める位置（応答の約 196 字目付近）の手前で打ち切り、全 800 出力が上限に当たり、「正解:」マーカーは 0 %。400 問の出力は 14 種類しかなく、**2 つの重みで 400/400 が一字一句同じ**。先頭 191 字は両者とも、指示の種類と選択肢の並びに応じた定型文（状態行の途中まで）で、確認した例では状態行の割り当ては正しい（全 400 問での正誤は未検証。番号の索引を使っている可能性が高い）。44.5 % という値は打ち切り位置の文字を拾っただけで、**何も測っていない**（上限を決めたのは私の設計ミス）。
- 参考：同じ 192 字までの出力が両チェックポイントで同一なので、差が出るのは、それ以降（答えの決定・結論）。

## 4. 次の測定と、事前に決める判定

生成に頼らず、**答えを決める文字だけを教師強制で測る**（決定論的、数分）。学習行と同じ書式の正しい途中経過（指示 → 状態行 → ALU 行）を与え、次の A/B/C の確率を読む：
- S1：状態行 1 行目の文字（含意の選択肢）、S2：2 行目（矛盾の選択肢）、FIN：「に合致するのは」の直後、COPY：「正解: 」の直後。
- 変形：(a) そのまま、(b) 前提の番号を入れ替えて**番号と型の対応を壊す**（内容は不変）、(c) 番号の引用を除く。選択肢の文字は 3 通りに回して位置の偏りを除く。
- 重み：30,500、40,500、61,500、次に中間（33,000、35,500、38,000、45,500、50,500、55,500、60,500）。

判定（事前登録）：主指標は (b) 変形での S1・S2・FIN 正解率（文脈単位、100）。同等の幅は ±8 点、3 対は Holm 補正、「有意でない」は「同じ」と読まない。結果は「低下／同等／判定不能」の 3 区分で、回復や改善も明示する。変形 (b) で崩れて (a) で保たれていれば「番号の近道に依存」、両方で保たれていれば出力形式や長さの問題、両方で落ちていれば表現そのものの低下。

並行して：元の条件（上限 2,048、最初の「正解:」で停止、全文保存）で 30,500 と 61,500 を各 200 問再現する（T4 と A100 の一致確認）。

## 5. 助言（暫定）

1. **v48 の学習方針はこれ以上続けない**（答えだけの教師、型が少ない、新教材 1.2 %）。61,500 の採用は §4 の結果まで保留。
2. 保護テストを学習の途中でも回す（2,500 更新ごと、教師強制で安い）。基準を下回れば止める。固定した錨（v43 と 30,500）への KL も記録する。今回の最大の見落としは、40,500 で T5 が一度も測られなかったこと。
3. 量を増やす（オーナーの指摘）：新教材の割合 1.2 % → 25 % 以上、更新回数を段階的に（20,000 更新ずつ、各段で評価）、問題の型を数百に、保留問題を 1,000 問以上に。答えを機械で検算できる分野（計算・Python 実行・論理の途中計算）は合成、読解と自然な日本語は人が作った既存データ（JGLUE の JSQuAD / JNLI / JCommonsenseQA の train：Drive に保存済み、GitHub の blob ハッシュで検証済み）を使う。ただし **JNLI の train は T5 の文の 559/589 を含む**ので、T5 と重なる対は学習から除く。
4. 教材の形式を揃える（T5 の「正解:」と v48 の「答え:」が競合する）。同じ少数行の 20 回提示は記憶に向かう。番号の手がかりが無い含意判定を足す。
5. 検索：知識は覚えさせず検索と読解で補う方針は維持。RustXNG は `/geosearch` で接続（出典は必ず表示）。
6. 1,000 更新の比較実験は、新教材 25 % なら v48 全体と同じ量（約 920 万 token）を見る。ただし「効かなかった」と断定せず、新型の保留問題で自明な答え方を明らかに超えたものだけを「効いた」とする。
