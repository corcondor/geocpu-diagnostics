# GeoCPU v48（40,500→61,500）評価の解析と、まだ分かっていないこと

**English TL;DR.** v48 (21,000 A100 updates, LR 3e-6, KL-anchored to the step-40,500 parent) taught the model the *output format*
of four new task families but not the skills: held-out accuracy 8–11 % overall (Japanese 25 % = 4-option chance), while the
symbolic/program tasks stayed high (T1 99.5 %, T2 88 %, T4-SWE 97.6 %). The legacy T5 (Japanese NLI with an operator instruction)
fell from 54.5 % (step 30,500) to 39.5 % (step 61,500). The step-40,500 value was **never measured**, so we cannot yet say whether the
drop happened inside v48 or earlier; the training signal (KL to parent ≈ 0.004) says v48 barely moved the model. A controlled
re-measurement with raw outputs on three checkpoints is queued on Kaggle T4×2. Review requested on §6.

> 注意：日時は 2026-11-09 時点。Kaggle の再測定は待ち行列中で、**この文書の「測定済み」はすべて A100（Colab）の元の評価と CPU 検査だけ**。

## 3. 解析

### 3.1 v48 は「ほとんど動かさなかった」
- 学習設定：バッチ 64、36,864 token/更新、LR 3e-6 固定、21,000 更新、親 40,500 への KL（重み 1.0）。
- 親への KL は 0.0017 → 0.0039。新データは教師 token の約 1.19 %、親の行 423,348 はすべて保存（旧教材の削除なし。T5 型の教材が親に含まれるかは未確認）。
- 予測：**61,500 の旧来の挙動は 40,500 とほぼ同じ**。T2（88.0 vs 88.0）、T3（25.77 vs 26.25、6/100 vs 6/100）はこの予測どおり。

### 3.2 では T5 の低下はどこで起きたか（未確定）
- 30,500 → 61,500 の T5 は −15.0 ポイント（対応のない検定で p≈2e-5。同じ問題なので本来は対応のある検定だが、問題ごとの正誤が保存されていない）。
- 3.1 の予測が正しければ、低下は v48 ではなく **30,500 → 40,500（v47 の 10k 更新、新規 848 行）で起きた**可能性が高い。ただし 40,500 の T5 が無いので**仮説**。
- 反対の仮説：T5 だけが微小な出力変化に敏感（答えの書式、開始位置）で、v48 でも落ちた。

### 3.3 T5 の問題は壊れていない
- 400 問すべてで、正解ラベルが「指示の種類 → 含意/矛盾/不明 → 文字」の対応表と一致（不一致 0/400）。100 の文脈は各 4 問、選択肢は文脈内で同一。
- 無作為 8 文脈を目視：含意＝言い換え、矛盾＝色・名詞の差し替え、不明＝情報の追加で、正解は妥当（全 400 問の意味までは検査していない）。
- T5 は「記号論理」ではなく**日本語の含意判定（JNLI 由来）**。「P |- Q」などは名前だけで、読解（前提と選択肢の突き合わせ）が要る。

### 3.4 39.5 % の意味
- 答えは 3 択（A/B/C）。一様な当て推量 33.3 % に対し 158/400 は有意に上（片側 p=0.006）→ 「偶然」とは言い切れない。
- ただし「問題を読まず、指示の種類ごとに最頻の文字を答える」戦略は 39.75 %（肯定含意なら B が 44 %）で、61,500 とは区別できない（p=0.56）。30,500 の 54.5 % はこの戦略を大きく上回る（p≈2e-9）。
- よって言えるのは「61,500 の T5 は読まない解き方と同等」。「技能が偶然水準」とは言っていない（T1/T2/SWE は高い）。

### 3.5 測定側の弱点（結論を縛る）
- **T5**：生成長の上限なし、答えは最初の「正解: X」か末尾の文字で拾う。**T5 の生出力は保存されていない**（Drive の出力フォルダで確認できたのは T4 の `tier4_raw.jsonl` のみ）ので、CPU で再採点できない。
- **T6**：固有の問いは 21 種（200 行は重複）、資料が合っておらず元の採点は検索結果の注入文も数える。T6 は 30,500 でも 0/200。
- **T7**：先頭 200 件が 2 科目だけ。**T8**：4 問。
- **JMMLU**：「A」を 80.5 % 選ぶ位置の偏り（23 % は偶然水準）。選択肢を回して測らないと内容を見ているか分からない。

## 4. 再測定（Kaggle T4×2、実行待ち）と、事前に決めた判定

同じ T4、同じ問題、同じ答えの取り出し方、生成上限つき（T5 192、T6 256）、**全生出力と停止理由を保存**、対応のある検定。

| 比較 | 見ること |
|---|---|
| 30,500 / 40,500 / 61,500 の T5 | 「正解:」の書式率、上限に当たった率、書式あり/なしの正解率 |
| JMMLU 4 回転 | 回転ごとの正解率、選んだ文字の割合、偏りを除いた正解率 |
| T6（v42 資料） | 答えが出た / モデル自身が書いた / 出た後に使った（注入文を除く） |

判定（事前）：
1. 40,500 ≈ 61,500 ≪ 30,500 なら、低下は v47 の 10k 更新で起きた。v48 は無罪で、原因は別（その段の新教材）。
2. 40,500 ≈ 30,500 ≫ 61,500 なら、v48 で本当に壊れた。61,500 は採用しない。
3. 3 つとも近い（書式率が違う）なら、T5 の採点・書式の問題。採点を直して全部測り直す。
4. 3 つの順に単調に下がるなら、継続学習の累積的な忘却。教材比率を見直す。

事前レビューで見つかり修正した不具合（Kaggle 実行前）：zip を Kaggle が展開してしまい固定ハッシュが検査できない（致命）、T6 の「使った」指標が注入文を数えて常に真（致命）、MCQ の進捗無表示・非再開・NaN の握りつぶし、部分結果への判定。

## 5. 助言（暫定）

1. **v48 の学習方針はこれ以上続けない**（答えだけの教師、型が少ない、新データ 1.2 %）。61,500 の採用は Kaggle の結果まで保留。
2. 旧来の保護テストを必ず付ける：T5 は上限と生出力保存つきで、**学習の各段階（30,500、40,500、…）で測る**。40,500 の T5 が欠けていたのが今回最大の見落とし。
3. 次の学習は A100 の前に **Kaggle T4 で 1,000 更新の一要因ずつの比較**（途中の計算を見せる教材 vs 答えだけ、新データ比率 1.2/10/25 %、LR 3e-6 vs 1e-5、KL 有無）。判定は T1〜T5 の非劣性と新型の向上を同時に。
4. 教材：新しい型を数百に増やし、構造が重ならない保留型を作る。evidence は本物の引用と紛らわしい文を入れる。
5. 知識は覚えさせず、検索と読解で補う方針（RustXNG を `/geosearch` で接続、出典は必ず表示）。

## 6. レビューしてほしい点

1. §3.1 の推論（KL≈0.004 → 旧来の挙動はほぼ不変）は妥当か。T5 だけが例外になり得る機構は何か。
2. §4 の判定規則は十分か。足りない対照（例：同じ T5 で 40,500 を A100 でも測る、位置の偏りのない T5 変形）は何か。
3. 統計：対応のない検定を使った箇所の扱い、多重比較、21 種の T6 を検定しない判断。
4. 教材設計（§5-4）と 1,000 更新の比較実験の設計に見落としはないか。
5. この文書の事実の誤り（ログ・数字）。数字の出典：各 `tier_N.log`、`v48_sets_rescored.json`、`input_manifest.json`、`oneshot_state.json`。
