# GeoCPU v48：不足領域を増やす追加教材（旧教材は削除しない）

**既存422,500行＋v47追加848行は一切減らさない。** 元T1〜T8、step40,500 checkpoint、学習中Colabも変更しない。

## A100での実行（2段階・11月8日）

| 段階 | ランタイム | 何をするか |
|---|---|---|
| ① CPU事前検査 | CPU | 423,348行をSHA256 `ba59c14b…`と行数で照合 → v48の4,096問を追加 → 旧教材の全ソースが40,500段階（30,500→40,500、同じ36,864トークン/更新・同じサンプラー）以上の教師トークンを得る最小の更新回数を、**1回の試算**で決める → SHA256つきの承認ファイルを`_v48_preflight/`に保存 |
| ② A100学習 | A100 40GB以上 | 承認ファイルとコード・重み・データのSHA256を照合して再利用（試算は繰り返さない）。`CONFIRM_UPDATES`に①の更新回数を書いたときだけ開始 |

以前の版が遅かった理由と直したこと:

- 学習データ（30500・40500）を毎回作り直していた → `_v48_dataset_cache/`にSHA256照合つきで保存し、2回目からは写すだけ（ハッシュが違えば使わない）。
- 更新回数の候補ごとにサンプラーを最初から試算していた（最大11回） → 1回の試算で全候補を記録し、条件を満たした時点で止める。v47の元の`preview_plan`と完全一致することを最初に確認し、その確認結果も保存して再利用する。
- 旧ソース2つ（`practical_python_multistep_v1`・`practical_knowledge_multistep_v1`、計848行）が、20,000更新でも40,500段階の量に届かなかった。前段階ではこの2つが新教材として16回反復されていたため。 → 不足するソースだけを**明示した重み**で反復して補う（PR #7）。重みは20,000更新の時点の不足から決め、GPU更新回数が最小になる計画を選ぶ。反復なしで必要な更新回数も報告に残す。反復行は独立した問題数に数えない。
- 補充の重みを自動で決めると、20,000更新の不足から重み8になり、21,000更新（約4.6時間）になった。旧ソースのうち不足するのは実用教材2つ（848行）だけで、前段階はこの2つを重み16で反復していた。→ `--replay-weights practical_python_multistep_v1=16,practical_knowledge_multistep_v1=16`で重みを明示すると、更新回数だけを計算で決める（全ソースが基準を満たす最初の回数）。ノートブックの既定はこちら。重みは各2〜32の整数で、範囲外・重複・存在しないソースは実行前に止まる。
- T4専用だった → 既定はA100。40,500段階と同じBF16・自動分割（OOMなら同じ更新を小さく分けてやり直す）。A100の40GB版と80GB版の違いだけは、新データ段階に限って再開を許す。

## 新規追加データ

| 領域 | train | dev | 未学習family用評価 |
|---|---:|---:|---:|
| Pythonコード生成・実行 | 1,024 | 128 | 128 |
| 論理・条件処理 | 1,024 | 128 | 128 |
| 多段資料読解 | 1,024 | 128 | 128 |
| 日本語の指示・否定・選択 | 1,024 | 128 | 128 |
| **合計** | **4,096** | **512** | **512** |

学習用4分野が同数になるのは「新たな追加分」の配分。**既存群の比率を下げたり、既存例を削除したりする意味ではない。**
各領域の難易度3〜4は768/1,024行（75%）。旧問題の単純な複製ではなく、複数条件・逆操作・段階的な根拠・否定を増やす。

## 多様性と限界

1領域32 familyを収録（基本8系統×4問形式）。ただし32 familyがすべて独立したアルゴリズムという意味ではない。
Pythonはフィルタ、移動窓、同一キーの最後の値、集合、行列、時系列、時刻、余りの複合処理を生成。
論理では同じ計算系列を道具なしで追跡するため、Pythonと一部構造が重なる。日本語では肯定と否定、条件の複合、答えの記号指定を変える。
多段資料読解は**架空の資料**を用いた演習であり、実世界の一般知識が増えるわけでも、検索APIの実呼出しを教えるわけでもない。
実世界のJMMLU・JamC-QA向上には、権利を確認した現実の資料からの検索・根拠使用教材が別途必要。

## 再生成と公開

Python標準ライブラリで独立再生成でき、旧語彙3,898字・文脈2048・Python実行出力の照合を行う。

    python generate_dataset.py --output data --verify

自作教材JSONL・manifestを**GitHubのprivateブランチ**へコミットするワークフローを付属。GitHub Actionsが成功するまで、教材本体の公開完了とはみなさない。
外部データセットの再配布権限・評価漏洩に配慮し、既存の第三者製問題はGitHubへ無断複製しない。

## 学習と評価（1本の流れ）

`GeoCPU_v48_Colab_40500_to_balanced.ipynb` は ①CPU事前検査 → ②A100学習 → ③評価 の3セルです。②と③は**同じA100セッションで続けて**実行します（学習が終わってから別作業にしない）。

- ②学習：`train_from_40500.py`。2026-11-08に21,000更新（40,500→61,500）を実行し、完走しました。露出ゲートは通過しています（旧17ソースの減少なし、新4ソースの教師トークンは±15%以内）。評価は③で行います。
- ③評価：`eval_v48_oneshot.py`。**問題・採点・生成条件は40,500のときと同一で、変えません。**
  1. CPU検査：学習ロックなし、チェックポイントの受領書、原本の評価ステージの`--preflight-only`が通ることを、生成の前に確認する。
  2. v48評価セット（学習に入れていないdev 512問・unseen_eval 512問、4領域×128問）を61,500と40,500の両方に同じ条件で当てる。問題ファイルは`data/manifest.json`のSHAで改変がないことを確認する。
  3. 元のT1〜T8（SWE 200、状態追跡 200、JamC-QA 2,309、JMMLUを含む8,100、…）を無変更の原本ステージで61,500に実行し、保存済みの40,500と`compare_results.py`で比べる。同じ条件で完了した測定にだけ差分を出す。
  4. 任意（`RUN_AUX = True`）：python120などの補助評価（40,500のときは約4時間）。
- 途中で止まっても、完了したスイートは再計算しません。`STAMP_EVAL`に前回の時刻を入れて再実行すると続きから始まります。
- v48評価セットの採点は「答え: X。」の最終行が参照値と完全一致し、かつEOSで終わったものだけを正答にします。Python領域は、Pythonを実行して答えた割合（`tool_grounded_exact`）も別に出します。
- テスト：`python -m unittest test_eval_v48_oneshot`（CPUのみ。実モデルの読込・GPU上の生成・Colab環境での依存解決は含まない）。
