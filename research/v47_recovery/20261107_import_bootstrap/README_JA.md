# 新しいColabセッションでの評価準備

## 修正する問題

前回のチャット評価セルは、学習セルで展開した `WORK` と `sys.path` が同じセッションに残っていることに依存していた。準備がない状態では最初の `from live_logging import run_with_logging` で `ModuleNotFoundError` が起き、評価開始前に停止する。

`live_logging.py` は配布ZIPに同梱された補助モジュールである。新しい準備セルはDriveをマウントし、固定SHAの10k ZIPを新しい `/content` 作業フォルダーへ展開し、読み込みパスを設定してから同梱モジュールをimportする。再実行時も古いWORKのimportキャッシュが混ざらないよう、当プロジェクトの6モジュールだけを読み直す。

## 実行方法

1. ColabのGPUランタイムで `colab_setup.py` の内容を準備セルとして実行する。
2. 「準備完了」を確認し、既に渡した評価セルを再実行する。

同梱の `GeoCPU_eval_40500_fresh_session_20261107.ipynb` は、この準備と全件評価の2コードセルを含む。元T1〜T8、Python補助試験、全件知識の検索なし／検索許可を40,500と30,500で比較する。元30,500のT1〜T8は保存済み原票を照合して再利用する。評価出力名は前のセルと一致し、同一条件の保存済み補助結果を `--resume` で再利用する。

この準備セルは学習やモデル推論を開始しない。保存済みチェックポイント、実行中プロセス、元のDriveファイルを変更せず、パッケージのインストールも行わない。既存の10k ZIPとそのSHAは変更していない。

## 検証範囲

`verification_cpu.json` に、外部モジュールを読み込めない新規Pythonプロセスでの再現と、同じ準備コードの実行後のimport・固定資産・評価計画の検査結果を記録する。DriveマウントだけはCPU検査用の代替を使い、パスを一時フォルダーへ置き換える。Colabの実機操作・GPU評価の検証ではない。
