## 2. 評価そのものについて分かったこと

- **T5**: 4 つの演算子について、正解の選択肢が引く前提番号は (1)(2)(3)(3) で、400 問すべてで一致します（確認）。番号の規則だけで 400/400 になります。T5 は「番号を追う力」を測っていて、文の内容を読む力ではありません（前の測定と同じ結論）。
- **T7 の 5.0%**: 4 択の偶然（25%）を大きく下回ります（確認: 200 問で 10 以下になる確率は 4.6×10⁻¹⁴）。同じ 200 問で、文字の確率を直接比べる方式では 19.0%（A が 188/200 回選ばれる）、偏りを除くと 27.0% です。生成を点数化する側の文字の取り出しの失敗の可能性が高いです。ただし T7 の生成そのものはディスクに残っておらず、原因は推定です。
- **T6**: 200 行だが問題は 21 種、検索の対象は 25 文書だけです。
- **T8**: 4 問・形だけの採点で、61,500 の結果は見つかっていません。

## 4. 8 系統（Hugging Face）の計画への影響

1. **JGLUE の JSQuAD は新しい材料ではありません。** 旧教材には JSQuAD 自体が入っていて、v49 の dev・heldout の質問の 47.5%、文章の冒頭の 79.3% が旧教材に一字一句ある（確認）。「新教材 25%」の数に入れるなら、先に旧教材との重複除去をしてからにします。JaQuAD は別の注釈なので新しい材料に近いですが、同じ Wikipedia の文章と重なる可能性は確認していません。
2. **T8 の C++ と Rust は、旧教材にも v48 にも v49 にも 0 行です。** この空白を埋められるのは、LLM-jp Coding のような多言語のコードの材料だけです。LLM-jp Coding に C++ と Rust が実際にあるかは、取得パイプラインの言語の標本で確かめます。
3. **v49 の 5 系統（42.11M、jglue 除く）は、計画の 8 系統に入っていません。** 答えが機械で検算済みという強みはあるが、使い回しの事実が多く近道が残る。8 系統で 58.25M に足りないときの穴埋め候補として取っておきます。入れるかどうかは決めていません。
4. **T7（解剖学・抽象代数）の知識を足せる材料はありません。** JMMLU の翻訳元（MMLU）から作った日本語の材料は、T7 の評価問題を汚すので使えません。
