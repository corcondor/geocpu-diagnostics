# GeoCPU v43 / v44 Python CoT 引き継ぎ記録

更新日: 2026-11-03（日本時間）

## 目的と現在の判定

v43 の保存重みを保全したまま、日本語の説明と Python の実行結果を行き来する学習を成立させる。性能維持、Python の自律呼び出し、日本語の回答品質は別々に評価する。現時点で追加学習後の三点を同時に満たした原票はない。

## 混同してはいけない三つの版

| 版 | 実行経路 | 観測 |
| --- | --- | --- |
| v43 step 15000 | CPU/ALU と検索 | 元の保存重み・ソースが残っている。Claude の診断書では SWE 12/12。 |
| v44 Python 一本化版 | ALU を外し、Python TIR に置換 | Release の実行記録は step 15000 のまま更新 0、`Inference tensors cannot be saved for backward` で停止。別の Hotfix 実験は 10,000 更新後に旧 SWE が低下したとの診断がある。 |
| Claude v44fix | v43 の CPU/検索を残し、Python を第三の道具として追加 | Claude の診断書は、Python を使わない生成で v43 とトークン列が一致したと報告。Drive の `run_1` には教材準備の原票だけがあり、追加学習後の保持評価は未確認。 |

純版の失敗を Claude v44fix の学習後成績として扱わない。Claude v44fix の学習前互換性を、学習後性能の証明として扱わない。

## ソースで確認した欠陥

1. 旧純版の Python 実行経路は、学習に渡すキャッシュを `torch.inference_mode()` で作る。保存済み Release の失敗文言と一致する。旧クラスと修正クラスを同じ小型モデルで比較すると、旧側だけ backward が失敗した。修正枝は勾配に使えるキャッシュを作る。
2. 元の v44fix データ変換は、Python が返した観測文を訓練ターゲットへ残す一方、公開教材の `target_segments` を最終学習データへ渡さない。学習器は観測文まで予測対象としていた。隔離修正枝では観測文を入力に残し、その位置の損失だけを 0 にする。
3. 公開教材の ` ```py` と大小文字違いのコードフェンスは、実行器が認識する ` ```python` と揃っていなかった。隔離修正枝で正規化し、行頭の実行条件を照合する。
4. 元 v44fix のチェックポイントは重みと step が中心で、Adam の状態、乱数、データ順・位置を保存しない。既存の `resume` は厳密な続きではない。単一系列のメモリ不足を損失 0 で通し、更新回数だけ進める箇所もある。これらは隔離枝で修正中であり、GPU 上での完了はまだ確認していない。
5. 元 v44fix の教材キャッシュと評価キャッシュは、修正ソース・チェックポイント・評価件数を十分に鍵へ含めない。古い結果の流用を防ぐ必要がある。

## 教材と評価の境界

Claude v44fix の既存混合データ manifest は 244,474 行：v43 保持 150,000、TIR 60,000、コード 19,474、日本語 15,000。TIR の元プールは 35,493 件なので、60,000 行を 60,000 種の問題とは数えない。公開教材の作成時に 72,441 件の TIR 行を読み、実行照合を試みたのは 16 件、通過は 13 件だった。最終の異なる TIR 35,493 件のうち、この照合を通ったものは最大 13 件であり、残りが誤っているという意味ではなく未照合である。既存 `run_1` の学習データは損失マスク修正前の生成物で、修正版へ再利用しない。

隔離修正枝は、採用する TIR 例に実行照合の記録を要求する入場条件を実装した。60,000 回の提示に対して検証済みの異なる例が 30,000 件未満なら学習を開始しない。既存の `run_1` の著者記録だけでは通過しない。全件照合の所要時間はまだ実測していない。

同じ保存重みと同じ入力形式で、旧 CPU/検索の保持、Python 呼び出し、日本語の原回答、反復、自然終了を分けて評価する。4 問の短い動作確認は性能の根拠にしない。現行の Claude v44fix は旧 7 分野評価と別の Python 評価を持つ。元の一本化版が掲げた Tier 1～8 を、現行版で全件完走したとは扱わない。

元 v43 の学習例は、公開教材の準備段階で一部を除外した後、最終混合データの作成時に元の訓練ファイルから再読込する。既存 manifest の最終 150,000 件には CPU 命令例 75,048 件、検索例 16,211 件がある。したがって「最終教材から旧 CPU/検索が消えた」は誤りである。ただし、これらの存在だけで学習後の能力保持は証明されない。

## 2026年11月3日の隔離修正と停止条件

- 元ソースを私有 GitHub リポジトリへバイト一致で保存した。隔離修正枝では、Python 観測文を正解文字として学習しないマスク、Adam・乱数・データ位置を含む保存再開、メモリ不足時の更新拒否を実装した。
- 検索結果に埋め込まれた Python コードをモデル自身が書いたコードと取り違えないようにした。Python コード内の CPU 命令文字列も CPU 実行へ渡さない。検索のソースと知識コーパスを評価結果の識別情報に含めた。
- 本学習への途中判定は、別の未学習 100 問のうち、Python 実行成功と最終正答が同じ問題で 10 件以上という条件へ変更した。これは本学習の成績ではない。
- CPU 上の小型検査は異なる 38 件が通過し、監査 ZIP の 56 ファイルのハッシュも一致した。Colab 上の学習更新、全評価、学習後の原回答は未実施である。
- 公開教材の Python は任意のコードを含み得る。既存実行器の時間・容量・AST 制限は、Drive と認証情報から隔離する OS の仕組みではない。安全な隔離環境で作った全件検証記録を固定するまで、監査 ZIP は `training_ready=false` とし、Colab 起動セルは学習前に停止する。
- 公開教材の検証器は一つの子プロセスを長く使う。現在の累積 CPU 制限 60 秒では全件照合が途中で停止する。1 例が時間切れになった場合にも子プロセスは閉じられ、次の例で再利用しようとすると停止する。隔離環境での子プロセス更新方法が必要である。著者の最終 `\boxed{}` 回答は別の正解表と突合していない。

## 次の実行条件

- v43 の元 ZIP と step 15000 重みは読み取り専用に固定する。
- 隔離枝のソース・教材・チェックポイントを SHA で固定する。存在しない／壊れた保存物からの初期化は拒否する。
- 1,000 更新の試走では、実データの勾配、マスク、保存・再開、同じ評価入力での旧能力と Python 呼び出しを確認する。旧版の 10,000 更新を再起動しない。
- 試走と本学習が別系列なら、それぞれ独立した結果として記録する。試走の合格を本学習の性能保証と呼ばない。
- 未学習評価問題と公開教材の重複を調べ、原回答と実行トレースを保存する。

## 他の実装者へのレビュー依頼

2. v43 形式・語彙・重み・CPU/検索経路の保持を、実生成でどう最小費用で証明するか。
3. 途中再開に必要な Adam、CPU/CUDA/Python 乱数、データ順・位置の保存と検証に抜けはないか。
4. 公開教材の反復・ツール出力の模倣・評価混入をどう検出するか。
5. Python の自律呼び出しと、日本語で根拠を示す説明の両方が伸びたかをどう評価するか。
